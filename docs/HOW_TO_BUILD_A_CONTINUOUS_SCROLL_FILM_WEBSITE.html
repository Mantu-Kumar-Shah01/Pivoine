Building Continuous Scroll-Film Web Experiences

An authoritative architectural blueprint for creating ultra-luxury, 60–120 FPS canvas-driven scroll experiences (inspired by Pivoine and Ascenta Studio).

Author: Antigravity Creative Engineering Target: WebGL / Canvas 2D + Worker Pool Status: Production-Grade

1. Executive Summary & Core Architecture

Modern luxury web storytelling relies on Continuous Scroll-Films: single unbroken camera journeys through a 3D physical or botanical space where the user's scroll position scrubs the camera with surgical precision.

The Fundamental Rule: Never Use the HTML5 <video> Element for Scrubbing.
Standard video seeks incur a hardware seek latency of 35–65 milliseconds per keyframe. When a user scrolls at normal speed, seeking cannot keep up, resulting in severe visual stuttering, dropped frames (~18 FPS ceiling), and frozen touch inertia on mobile iOS Safari.
Dimension Conventional <video> Scrubbing Continuous Scroll-Film Engine (Canvas + WebP)
Rendering Primitive <video currentTime=...> (Seek lag) HTML5 <canvas> `{ alpha: false }` (Direct GPU blit)
Frame Rate 15–22 FPS during active scroll 60 to 120 FPS locked display refresh rate
Image Decoding Main JS thread (causes UI freezes) Multi-Threaded Web Workers via createImageBitmap
Memory Management Unbounded buffer, causes mobile crashes Sliding Cache Window (36–48 frames) with explicit .close()

2. The 4-Tier Memory & Worker Architecture

To support sequences of 700 to 1,200 high-resolution frames without exceeding mobile memory budgets (~250MB WebKit Jetsam limit), the system utilizes a 4-tier progressive streaming architecture:

[ User Smooth Scrolls via Lenis ] │ ▼ [ Compute Target Frame Cursor ] ──► Eased with Exponential Tau Filter (22ms) │ ├──► TIER 1: Compressed WebP Memory Blobs (Loaded coarse-to-fine: Step 64 → 32 → 1) │ ├──► TIER 2: Sliding Decoded Window (36-48 ImageBitmaps in GPU memory) │ ├──► TIER 3: Web Worker Pool (Zero-copy off-thread image decodes) │ └──► TIER 4: Explicit Disposal (Calls bmp.close() when frame leaves window)

Sliding Window Cache

Retains only 36–48 decoded frames around the active cursor. Discards furthest frames behind the scroll direction to ensure minimal RAM usage.

Zero-Copy Worker Transfer

Decodes image bytes off the main UI thread via createImageBitmap(blob) and transfers ownership with zero memory duplication.

3. Asset Production & AI Frame Interpolation

How to produce continuous photorealistic product journeys from scratch:

Step 1: 3D Render or Generative AI Video

  • Generative AI (Kling AI / Runway Gen-3): Prompt for slow, continuous macro camera movement (e.g. "Slow macro camera tracking down into blooming peony petals, crystal cosmetic jar rising, studio lighting...").
  • 3D Software (Blender / Cinema 4D): Set a smooth Bezier camera path around your product and export a clean 10–14 second sequence at 24/30 FPS.

Step 2: RIFE 4x AI Frame Interpolation (Crucial)

A 10-second video has only 240 frames. Over a 4,000px page scroll, each frame lasts ~16px of scroll distance (feels like a slideshow). Passing the sequence through RIFE AI at 4x produces 960 to 1,200 continuous frames. The pixel delta drops to ~2.5px per step for absolute fluidity.

Step 3: WebP Batch Compression with FFmpeg

# Extract frames to ultra-lightweight WebP sequence
ffmpeg -i product_animation.mp4 -vf "fps=60,scale=1920:1080" -vcodec libwebp -quality 82 -lossless 0 -compression_level 4 frames/f_%04d.webp

4. Dual-Reel Art Direction & Typography

Desktop Composition (16:9)

Product kept in the center-right area (focal point fx: 0.6). The left 30% remains clean negative space for editorial typography and actions.

Mobile Composition (9:16)

Product positioned in the lower 60% of the viewport. Headlines sit anchored in the top 40% so text never occludes the product.

5. Production Implementation Code

1. Web Worker Multi-Threaded Decoder

// Web Worker (Off-Thread Image Decoder)
onmessage = async (e) => {
  const { id, url } = e.data;
  try {
    const res = await fetch(url);
    if (!res.ok) throw new Error('HTTP ' + res.status);
    const blob = await res.blob();
    const bmp = await createImageBitmap(blob);
    postMessage({ id, bmp }, [bmp]); // Zero-copy transferable ownership
  } catch (err) {
    postMessage({ id, err: true });
  }
};

2. Canvas Blit & Physics Loop (`film-engine.js`)

const canvas = document.getElementById("film");
const ctx = canvas.getContext("2d", { alpha: false }); // Opaque 2D context
const EASE_TAU = 22; // Inertia time-constant (ms)

function renderLoop(time) {
  const dt = time - lastTime;
  lastTime = time;

  // Exponential smoothing prevents frame skipping
  const delta = targetFrame - curFrame;
  curFrame = Math.abs(delta) > 0.001 
    ? curFrame + delta * (1 - Math.exp(-Math.min(dt, 50) / EASE_TAU)) 
    : targetFrame;

  scheduleLookaheadDecodes();
  drawCoverFitCanvas();

  requestAnimationFrame(renderLoop);
}

// Lenis Smooth Scroll Listener
const lenis = new Lenis({ lerp: 0.12, smoothWheel: true });
lenis.on("scroll", ({ scroll }) => {
  const maxScroll = document.body.scrollHeight - window.innerHeight;
  targetFrame = (scroll / maxScroll) * (TOTAL_FRAMES - 1);
});

6. Production Checklist & Mobile Guardrails

  • ✔ Opaque Canvas Context: Always initialize with getContext("2d", { alpha: false }) to skip unnecessary GPU alpha compositing.
  • ✔ Explicit Memory Deallocation: Always invoke imageBitmap.close() upon cache eviction. Browsers will not trigger GC fast enough during rapid scrubbing.
  • ✔ Stable Viewport Units: Use 100svh and 100lvh to protect against mobile URL bar resize jitter.
  • ✔ APCA Contrast Compliance: Maintain an APCA lightness contrast rating > 80 for text placed on top of moving video backgrounds.
